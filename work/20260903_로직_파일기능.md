# autoRPG 개발 로직 · 파일 기능 정리

- 작성일: 2026-09-03
- 기준 브랜치: `work/dungeon-run`
- 목적: 현재까지 구현된 시스템의 구조, 파일별 책임, 주요 계산 공식과 데이터 흐름을 한 곳에서 확인하기 위한 개발 기준 문서

## 2. index.html — 게임 진입점과 모듈 로딩 순서

`work/index.html`

### 역할
- 게임 화면의 기본 DOM을 제공한다.
- 던전/여관/상점/기타 탭을 제공한다.
- 지역/던전/Seed/탐험 버튼을 제공한다.
- 파티 UI를 탭 버튼 바로 아래에 고정 배치한다.
- 게임 로직 JavaScript 파일을 의존성 순서대로 로드한다.
- XML 로더들을 초기화한 후 지역/던전/UI를 동기화한다.

### 현재 UI 구조

```text
헤더
 └─ 탭 버튼
     ├─ 던전
     ├─ 여관
     ├─ 상점
     └─ 기타

파티 정보 ← 탭 전환과 관계없이 항상 표시

지역 / 던전 / Seed / 탐험 제어

선택된 탭 내용
```

파티 UI는 별도 탭 안에 복제하지 않고 `#party` 하나를 `PartyPanel`이 관리한다.

## 3. Core

### `src/core/SeededRandom.js`

Seed 기반 난수 시스템.

주요 함수:
- `next()` → 0 이상 1 미만의 난수
- `int(min,max)` → 정수 난수
- `pick(items)` → 배열에서 하나 선택

핵심:

```text
seed → 반복 가능한 난수열
```

따라서 같은 Seed와 같은 실행 순서라면 전투/드랍/조우 등의 랜덤 결과를 재현할 수 있다.

### `src/core/GameState.js`

게임 전체 상태의 기본 구조를 만든다.

현재 기본 상태:

```js
{
  version: 1,
  seed,
  player: {
    gold: 100,
    characters: [],
    inventory: [],
    resources: {}
  },
  world: {
    townId: 'town.start',
    dungeonId: null,
    floor: 0,
    flags: {}
  },
  adventure: { active:false, currentEvent:null },
  battle: { active:false, state:null },
  logs: []
}
```

### `src/core/InventorySystem.js`

장비 인스턴스를 실제 인벤토리에 추가/삭제/조회한다.

주요 함수:
- `addLootInstance(item)`
- `getInventory()`
- `removeInventoryInstance(instanceId)`
- `setGameStateForInventory(state)`

장비는 단순 ID 하나가 아니라 `instanceId`를 가진 개별 인스턴스로 관리한다.

## 4. 캐릭터 시스템

### `src/battle/Character.js`

실제 전투에 사용되는 캐릭터 객체.

기본 전투 스탯:

```text
baseStats.hp
baseStats.attack
baseStats.defense
baseStats.speed
```

현재 전투 스탯:

```text
maxHp
attack
defense
speed
```

장비 장착 시:

```text
현재 HP = 기본 HP + 장비 HP
현재 공격 = 기본 공격 + 장비 공격
현재 방어 = 기본 방어 + 장비 방어
현재 속도 = 기본 속도 + 장비 속도
```

장비는 `weapon / armor / accessory` 세 슬롯을 사용한다.

장착 가능 여부는 다음을 검사한다.

```text
직업 제한
+ 능력치 요구조건
+ 요구 레벨
```

### `src/character/CharacterFactory.js`

캐릭터 원형/직업 데이터를 이용해 실제 `Character`를 생성한다.

현재 기본 직업:

| 직업 | HP | 공격 | 방어 | 속도 | 스킬 |
|---|---:|---:|---:|---:|---|
| 전사 | 450 | 62 | 35 | 12 | 강타 |
| 마법사 | 280 | 78 | 16 | 11 | 화염구 |
| 도적 | 320 | 55 | 22 | 18 | 연속 베기 |

실제 게임 파티의 더미 데이터는 `dummy-party.js`에서 관리한다.

### `src/character/CharacterProgression.js`

레벨/경험치와 레벨업 성장치를 담당한다.

최대 레벨:

```text
50
```

다음 레벨 필요 EXP:

```text
EXP_required(level)
= round(100 × level^1.35)
```

직업별 레벨업 성장:

| 직업 | HP | 공격 | 방어 | 속도 |
|---|---:|---:|---:|---:|
| 전사 | +32 | +4 | +2 | +0.15 |
| 마법사 | +20 | +5 | +1 | +0.12 |
| 도적 | +24 | +4 | +1.3 | +0.20 |

레벨업마다:

```text
STR +1
INT +1
AGI +1
VIT +1
```

레벨업 후 HP는 최대 HP로 회복된다.

## 6. 전투 시스템

### `src/battle/BattleEngine.js`

실제 턴 전투를 진행한다.

기본 제한:

```text
최대 60 Round
```

매 라운드:

1. 살아있는 캐릭터 수집
2. Speed 내림차순 정렬
3. Speed가 같으면 RNG로 순서 결정
4. 대상 선택
5. 스킬 사용 가능 여부 판단
6. 공격
7. 결과 검사

플레이어 대상:
- 현재 살아있는 적 중 HP가 가장 낮은 대상

적 대상:
- 전열/중열/후열 가중치 사용
- 전열 60%
- 중열 30%
- 후열 10%

전투 결과:

```text
적 전멸 → WIN
플레이어 전멸 → LOSE
60 Round까지 끝나지 않음 → LOSE / TIMEOUT
```

### `src/battle/DamageCalculator.js`

일반 공격의 실제 피해를 계산한다.

먼저 1~6 두 개의 주사위를 굴린다.

```text
roll = d6 + d6
```

특수:

```text
roll = 12 → Critical
roll = 2  → Fumble
```

명중:

```text
Fumble이면 무조건 Miss
그 외 일반 공격은 85% 명중
Critical은 명중
```

기본 피해:

```text
rawDamage = max(1, 공격자 공격력 + roll - 방어자 방어력)
```

최종 일반 공격:

```text
Miss     → 0
Normal   → rawDamage
Critical → rawDamage × 2
```

스킬 공격은 명중했을 경우:

```text
skillDamage = floor(baseDamage × skill.multiplier)
```

연속 베기는 동일 스킬로 추가 1회를 더 공격한다.

현재 기본값:

```text

```

다만 현재 실제 XML 몬스터 전투에서는 `BattleBalanceCalculator`가 우선 사용되며, 이 파일은 범용 스케일링 모델로 남아 있다.

## 8. 실제 몬스터 전투 밸런스 계산

### `src/world/BattleBalanceCalculator.js`

현재 전투 밸런스의 핵심 파일.

목표:
- 플레이어 파티 수준에 맞춰 몬스터 HP/공격을 계산
- XML에 있는 원본 HP/공격을 그대로 전투에 사용하지 않음
- 장비 착용 상태까지 고려한 파티 DPS/생존력을 이용

난이도 목표:

| 등급 | 플레이어가 몬스터를 처치하는 목표 | 파티 생존 목표 |
|---|---:|---:|
| Normal | 2.5 Round | 45 Round |
| Rare | 4 Round | 24 Round |
| Boss | 9 Round | 20 Round |

### 파티 DPS 계산

기본 기대 공격 피해는 36개의 d6+d6 결과를 모두 평가한다.

```text
ExpectedDamagePerAttack
= Σ(각 roll의 기대 피해) / 36
```

일반 roll:

```text
0.85 × max(1, Attack + roll - Defense)
```

Critical roll 12:

```text
2 × max(1, Attack + 12 - Defense)
```

Fumble roll 2는 피해 계산에서 제외한다.

### 스킬 포함 DPR

스킬이 없으면:

```text
DPR = 기본 기대 공격 피해
```

스킬이 있으면:

```text
SkillDamage
= ExpectedDamagePerAttack × SkillMultiplier × HitCount

DPR
= (SkillDamage + BaseDamage × Cooldown)
  / (Cooldown + 1)
```

### 몬스터 HP

목표 처치 라운드가 `T`이고 파티 기대 DPR이 `DPR`이면:

```text
MonsterHP = round(DPR × T)
```

### 몬스터 공격력

플레이어 파티 전체 HP와 몬스터의 예상 라운드 생존 목표를 이용해 이분 탐색으로 공격력을 찾는다.

진형 공격 가중치:

```text
전열 60%
중열 30%
후열 10%
```

예상 incoming DPR:

```text
IncomingDPR
= Σ(진형가중치 × ExpectedDamagePerAttack)
```

파티 생존 라운드:

```text
SurvivalRounds
= TotalPartyHP / IncomingDPR
```

이 값이 목표 생존 라운드 이상이 되도록 몬스터 공격력을 탐색한다.

최종적으로 최소 장비 파티와 최대 장비 파티에서 계산한 공격력을 평균하여 사용한다.

## 10. DungeonRun — 실제 던전 진행 관리자

### `src/world/DungeonRun.js`

게임 플레이에서 가장 중요한 흐름 제어 파일.

관리 상태:

```text
floor
encounterIndex
active
complete
failed
bossReady
gold
exp
loot
events
currentBattle
stats
```

### 일반 진행

```text
던전 시작
 ↓
구역 진입
 ↓
조우 결정
 ↓
몬스터 XML 조회
 ↓
BattleBalanceCalculator로 실제 HP/ATK 계산
 ↓
BattleEngine 전투
 ↓
승리
 ├─ EXP 지급
 ├─ 장비 드랍 판정
 └─ 로그 기록
 ↓
다음 조우
 ↓
구역 완료
 ↓
다음 구역 또는 보스 준비
```

현재 일반 구역은 기본적으로 최대 5회 조우를 기준으로 진행한다.

### EXP 분배

전투에서 얻는 몬스터 EXP 합계를 파티 인원수로 균등 분배한다.

```text
PartyEXP = Σ 몬스터 EXP
BaseShare = floor(PartyEXP / PartySize)
```

나머지는 앞쪽 캐릭터부터 1씩 추가한다.

### `currentAreaLevel(enemies)`

드랍 레벨 계산 등에 사용하는 실제 몬스터 레벨:

```text
AreaLevel = 최대 몬스터 레벨
```

최종 범위는 1~50으로 제한한다.

BattleBalanceCalculator.calculateMonsterStats()

## 12. 장비 데이터 구조

### `equipment_data_lvl1_25.xml`
### `equipment_data_lvl26_50.xml`

장비의 원본 데이터.

주요 필드:

```text
id
Name
Type
Grade
Value
ReqLevel
ReqStat
```

현재 XML에서:

```text
Value type="Attack" → attack
Value type="Defense" → defense
Grade              → rarity
ReqLevel           → reqLevel
ReqStat             → requirements.stats
```

### 중요한 원칙

**XML은 장비 원본/기준 데이터다.**

현재 드랍 생성 시 등급 자체에 추가 공격력 배율을 곱하지 않는다.

즉 현재 설계에서는:

```text
XML 기본 수치
+ 강화 배율
+ 등급별 옵션
```

구조이며, 예전의 `rarityMultiplier`는 제거되었다.

## 14. LootSystem — 장비 드랍 계산

### `src/world/LootSystem.js`

현재 장비 드랍의 핵심 파일.

### 일반 몬스터 장비 드랍 확률

```text
5%
```

전투 승리 후 장비 드랍을 시도한다.

```text
RNG > 0.05 → 장비 없음
RNG ≤ 0.05 → 장비 생성
```

### 드랍 장비 레벨 제한

처치 몬스터 레벨을 `L`이라고 하면:

```text
L - 3 ~ L + 3
```

단, 전체 게임 레벨 범위인 1~50으로 Clamp한다.

```text
MinLevel = max(1, L - 3)
MaxLevel = min(50, L + 3)
```

여기서 실제 비교 기준은 현재 XML의 `ReqLevel`이다.

### 등급 확률

장비가 드랍된 이후 등급을 별도로 추첨한다.

| 등급 | 가중치 | 실질 확률 |
|---|---:|---:|
| Uncommon | 60 | 60% |
| Common | 25 | 25% |
| Rare | 10 | 10% |
| Unique | 4 | 4% |
| Legendary | 1 | 1% |

합계 100.

### 강화 확률

| 강화 | 가중치 | 확률 |
|---|---:|---:|
| +0 | 80 | 80% |
| +1 | 15 | 15% |
| +2 | 5 | 5% |

### 강화 배율

강화만 장비 기본 수치에 배율을 적용한다.

```text
+0 → ×1.00
+1 → ×1.08
+2 → ×1.18
```

### 등급 배율

현재 **없음**.

```text
rarityMultiplier = 제거
```

따라서 등급이 높다고 해서 XML 공격력 자체가 자동으로 1.15배/1.35배/1.7배/2.2배 되는 구조가 아니다.

### 등급별 옵션 개수

| 등급 | 옵션 개수 |
|---|---:|
| Common | 0 |
| Uncommon | 1 |
| Rare | 1 |
| Unique | 2 |
| Legendary | 3 |

### 옵션

현재 옵션 후보:

| 옵션 | 스탯 | 범위 |
|---|---|---:|
| 힘 | attack | +2 ~ +6 |
| 수호 | defense | +2 ~ +6 |
| 민첩 | speed | +1 ~ +2 |
| 생명 | hp | +10 ~ +30 |

같은 옵션은 한 아이템에서 중복되지 않는다.

### 최종 장비 수치 공식

장비 원본 수치를 `Base`라고 할 때:

```text
EnhancementMultiplier =
  +0 → 1.00
  +1 → 1.08
  +2 → 1.18
```

옵션 보너스를 `OptionBonus`라고 하면:

```text
FinalStat
= round(BaseStat × EnhancementMultiplier)
  + OptionBonus
```

예:

```text
XML 공격력 = 100
강화 = +1
힘 옵션 = +5

최종 공격력
= round(100 × 1.08) + 5
= 108 + 5
= 113
```

**등급 배율은 여기에 들어가지 않는다.**

### 강제 드랍

`force:true` 또는 특정 `baseId`를 지정하는 보물/이벤트성 장비는 일반 5% 확률 판정을 우회할 수 있다.

따라서:

```text
일반 몬스터 드랍 = 5% 판정
강제 이벤트 장비 = 확률 판정 우회 가능
보스 = 현재 bossDropChance 100%
```

## 25. 현재 장비 최종 수치 계산 예시

가정:

```text
XML Base Attack = 100
등급 = Rare
강화 = +2
옵션 = 힘 +4
```

현재 공식:

```text
강화 배율 = 1.18
등급 배율 = 없음

최종 공격력
= round(100 × 1.18) + 4
= 118 + 4
= 122
```

Rare라고 해서:

```text
100 × 1.35
```

를 추가로 적용하지 않는다.

Rare의 차이는 현재:

```text
Rare
→ 옵션 1개
→ Rare 등급 표시
→ Rare 등급 가중치 10%
```

이다.

Unique/Legendary는 옵션 개수가 증가한다.

## 26. 드랍 확률을 해석하는 방법

현재 일반 전투 1회에서:

```text
장비가 나올 확률 = 5%
```

장비가 나온 뒤에는 다시:

```text
Common      25%
Uncommon    60%
Rare        10%
Unique       4%
Legendary    1%
```

등급을 선택한다.

따라서 일반 전투 1회 기준 이론적 결합 확률은:

```text
Common     = 5% × 25% = 1.25%
Uncommon   = 5% × 60% = 3.00%
Rare       = 5% × 10% = 0.50%
Unique     = 5% × 4%  = 0.20%
Legendary  = 5% × 1%  = 0.05%
```

단, 이는 `force`나 보스 드랍을 제외한 일반 장비 드랍 기준이다.

## 27. 현재 구현에서 주의할 점

### 1) `MonsterScaling.js`와 `BattleBalanceCalculator.js`를 혼동하지 말 것

현재 XML 몬스터의 실제 전투 HP/ATK 계산은 `BattleBalanceCalculator`가 핵심이다.

### 2) 장비 XML 수치와 실제 드랍 인스턴스 수치는 다를 수 있음

XML은 Base다.

실제 드랍은:

```text
XML Base
× 강화 배율
+ 옵션
```

이다.

### 3) 등급 배율은 현재 존재하지 않음

향후 다시 등급별 수치 배율을 추가하려면 `LootSystem.js`를 수정해야 한다.

### 4) `ReqLevel`이 현재 드랍 레벨 필터 기준

별도의 ItemLevel 필드가 존재하지 않는 현재 XML 구조에서는:

```text
몬스터 레벨 ±3
```

을 장비의 `ReqLevel`에 적용한다.

### 5) 보스는 일반 몬스터와 드랍 규칙이 다름

현재:

```text
일반 = 5%
보스 = 100%
```

이다.

### 6) 강제 이벤트 장비는 일반 드랍 확률을 따르지 않을 수 있음

보물/특정 이벤트에서 `force:true` 또는 `baseId`가 사용된다.

## 30. 현재 기준 개발 원칙

1. **XML 원본 데이터와 계산 결과를 구분한다.**
2. **게임 밸런스 공식은 가능한 한 전용 계산 파일에 둔다.**
3. **UI 파일에서 전투/드랍 계산을 직접 만들지 않는다.**
4. **장비는 개별 `instanceId`를 가진 인스턴스로 관리한다.**
5. **Seed 기반 RNG를 사용해 테스트 재현성을 유지한다.**
6. **사용자 화면에서는 `구역` 용어를 사용한다.**
7. **던전 진행 중 지역/장비/상점 관련 변경은 잠근다.**
8. **현재 장비 등급은 추가 수치 배율이 아니라 등급/옵션 구조로 처리한다.**
9. **새 밸런스 수치를 추가할 때는 하드코딩을 여러 파일에 흩뿌리지 않고 관련 CONFIG/데이터 파일에 집중한다.**
10. **밸런스 변경 후 `DungeonBalance` 시뮬레이션으로 실제 전투 결과를 확인한다.**
