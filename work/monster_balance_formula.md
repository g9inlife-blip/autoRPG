# 몬스터 밸런스 수식 설계

> 기준: `work/dungeon-run`
> 목적: 캐릭터의 **현재 전투력에 몬스터가 따라가는 동적 스케일링**을 제거하고, **레벨별 고정 기준 전투력**으로 몬스터의 HP/ATK를 산정한다.

## 1. 핵심 원칙

몬스터는 플레이어의 현재 장비나 현재 능력치를 보고 실시간으로 강해지지 않는다.

잘못된 구조:

```text
현재 캐릭터 ATK 증가
→ 현재 파티 DPS 증가
→ 현재 몬스터 HP 증가
```

이 구조에서는 캐릭터가 강해져도 같은 레벨의 몬스터를 잡는 시간이 유지되므로 성장감이 약해진다.

현재 적용하는 구조:

```text
레벨 L의 고정 캐릭터 기준치
+ 레벨 L의 고정 장비 기준치
→ 최소/최대 DPS 계산
→ 레벨 L 몬스터 HP 기준값 계산
→ 몬스터 등급/역할 계수 적용
→ 몬스터 HP 확정

레벨 L의 고정 캐릭터 생존 기준치
→ 몬스터 ATK 계산
→ 몬스터 ATK 확정
```

실제 게임에서는 확정된 몬스터 스탯을 사용한다.

```text
플레이어 장비 강화
→ 플레이어 DPS 증가
→ 기존 몬스터를 더 빨리 처치

플레이어 레벨 상승
→ 저레벨 몬스터를 더 빨리 처치
→ 고레벨 지역으로 진행
```

즉, **몬스터 스케일링과 플레이어 성장을 분리**한다.

---

## 2. 밸런스 기준 캐릭터

각 레벨 `L (1~50)`에 대해 전사/마법사/도적을 별도의 기준 캐릭터로 만든다.

캐릭터 기본 능력치는 실제 캐릭터 클래스 정의를 사용하고, 레벨 성장 규칙을 적용한다.

```text
기준 캐릭터(L, class)
= 해당 클래스 Lv.1 실제 능력치
  + 실제 CharacterProgression 성장 규칙을 Lv.L까지 적용
```

밸런스 계산은 실제 플레이어가 현재 어떤 장비를 착용했는지와 무관하다.

---

## 3. 레벨별 장비 기준

각 기준 캐릭터에는 해당 레벨에서 장착 가능한 장비 중 슬롯별 최고 기준 장비를 적용한다.

현재 원칙:

```text
무기      → Attack 최고값
방어구    → Defense 최고값
장신구    → Attack + Defense 최고값
```

단, 실제 장착 가능 여부(`class`, `level`, `stat` 요구사항)는 `Character.canEquip()`을 통과해야 한다.

따라서 장비 데이터가 변경되면 밸런스 계산 결과도 자동으로 변경된다.

중요한 점은 **게임 플레이 중 장비를 바꿀 때 몬스터가 재계산되는 것이 아니라**, 밸런스 계산 시 해당 레벨의 기준 장비가 다시 계산된다는 것이다.

---

## 4. 공격 기대값

현재 `DamageCalculator`의 전투 규칙과 일치하도록 2d6 전체 36개 결과를 계산한다.

각 공격의 기대 피해량:

```text
roll = d1 + d2

roll = 2
→ Fumble
→ 피해 0

roll = 12
→ Critical
→ rawDamage × 2

그 외
→ 85% 명중
→ rawDamage × 0.85
```

기본 피해:

```text
rawDamage = max(1, Attack + roll - Defense)
```

따라서:

```text
ExpectedDamage(ATK, DEF)
= Σ(36개 2d6 결과의 실제 기대 피해) / 36
```

스킬 배율이 `M`이면:

```text
ExpectedSkillDamage
= ExpectedDamage(ATK, DEF, M)
```

---

## 5. 스킬을 포함한 DPR

캐릭터에게 스킬이 없는 경우:

```text
DPR = 기본 공격 기대 피해
```

스킬의 쿨다운이 `C`이고 배율이 `M`이면 한 사이클을 다음처럼 본다.

```text
스킬 1회
+ 기본 공격 C회
```

따라서:

```text
DPR
= (SkillExpectedDamage + BaseExpectedDamage × C) / (C + 1)
```

도적처럼 추가 타격(`extraHit`)이 있는 스킬은 스킬 기대 피해에 추가 타격 수를 반영한다.

---

## 6. 파티 DPS

현재 기준 파티는 전사/마법사/도적 3명이다.

몬스터 방어력을 `DEFm`이라고 할 때:

```text
PartyDPS(L, DEFm)
= WarriorDPR(L, DEFm)
+ MageDPR(L, DEFm)
+ RogueDPR(L, DEFm)
```

중요: 몬스터 방어력은 XML의 실제 값을 사용한다.

즉 HP/ATK를 수식으로 산정하더라도 **DEF는 기존 몬스터 데이터의 실제 값이 기준**이다.

---

## 7. 몬스터 HP 산식

몬스터 등급별 목표 TTK를 사용한다.

현재 기본값:

| 등급 | 목표 TTK |
|---|---:|
| 일반 | 2.5 라운드 |
| 희귀 | 4.0 라운드 |
| 보스 | 9.0 라운드 |

몬스터의 레벨을 `L`, 방어력을 `DEFm`, 목표 TTK를 `T`라고 하면:

```text
MonsterHP
= PartyDPS(L, DEFm) × T
```

정수화 후 최소 1 이상으로 제한한다.

```text
HP = max(1, round(PartyDPS × T))
```

현재 구현에는 과도하게 큰 값이 나오는 것을 방지하기 위한 최대 HP 제한도 존재한다.

---

## 8. 왜 최소/최대 DPS를 별도로 보는가?

밸런스 검증에서는 한 가지 캐릭터 상태만 보는 것보다 해당 레벨에서 가능한 전투력 범위를 확인하는 것이 중요하다.

개념적으로:

```text
Lv.L

최소 기준 전투력
        ↓
    Minimum DPS

최대 기준 전투력
        ↓
    Maximum DPS
```

이 범위를 이용하면 이후 밸런스 조정 시 다음과 같은 정책을 적용할 수 있다.

```text
최소 DPS 기준 TTK
→ 장비가 약한 플레이어의 전투 난이도 확인

최대 DPS 기준 TTK
→ 장비가 좋은 플레이어의 성장 체감 확인
```

현재 구현은 우선 **레벨별 기준 캐릭터 + 최고 장비를 이용한 고정 기준 DPS**를 게임 내 몬스터 산정에 사용하고 있으며, 최소/최대 범위 계산은 향후 밸런스 검증을 확장할 수 있는 구조로 유지한다.

---

## 9. 몬스터 ATK 산식

몬스터 ATK 역시 현재 플레이어의 방어력에 따라 실시간으로 변경하지 않는다.

해당 몬스터 레벨 `L`의 기준 캐릭터 생존력을 이용한다.

등급별 생존 배율:

| 등급 | 생존 배율 |
|---|---:|
| 일반 | 2.0 |
| 희귀 | 1.5 |
| 보스 | 1.25 |

목표 TTK가 `T`이면 기준 생존 라운드는:

```text
DesiredSurvivalRounds
= T × SurvivalMultiplier
```

기준 파티에서 가장 낮은 HP를 가진 캐릭터를 생존 기준으로 선택한다.

```text
DesiredIncomingDPR
= WeakestHP / DesiredSurvivalRounds
```

그 다음 몬스터 ATK를 탐색하여:

```text
ExpectedDamage(MonsterATK, WeakestDEF)
≤ DesiredIncomingDPR
```

을 만족하는 가장 큰 ATK를 선택한다.

현재 구현에서는 이 값을 이진 탐색으로 찾는다.

---

## 10. 등급별 난이도 구조

현재 기본 난이도는 다음과 같다.

```text
일반
→ 2.5R에 처치 목표
→ 플레이어 생존 기준 5.0R

희귀
→ 4.0R에 처치 목표
→ 플레이어 생존 기준 6.0R

보스
→ 9.0R에 처치 목표
→ 플레이어 생존 기준 11.25R
```

이는 최종 밸런스가 아니라 **조정 가능한 기본값**이다.

예를 들어 보스가 너무 약하면:

```text
boss.ttkRounds
9.0 → 10.0
```

또는 너무 오래 걸리면:

```text
boss.ttkRounds
9.0 → 8.0
```

처럼 전체 보스 밸런스를 한 번에 조정할 수 있다.

---

## 11. 레벨 차이에 따른 실제 전투시간

이 구조의 가장 중요한 효과다.

Lv.30 몬스터의 HP가 Lv.30 기준 전투력으로 확정되었다고 가정한다.

```text
Lv.30 캐릭터
→ Lv.30 몬스터
→ 기준 TTK

Lv.40 캐릭터
→ 동일 Lv.30 몬스터
→ DPS 증가
→ TTK 감소

Lv.50 캐릭터
→ 동일 Lv.30 몬스터
→ DPS가 훨씬 높음
→ TTK 크게 감소
```

따라서 낮은 지역이 고레벨 캐릭터에게 점점 쉬워지는 자연스러운 성장감이 생긴다.

반대로 Lv.50 지역에서는 Lv.50 기준 몬스터가 존재하므로:

```text
Lv.50 캐릭터
→ Lv.50 몬스터
→ 다시 적정 TTK
```

가 된다.

---

## 12. XML 데이터의 역할

현재 XML의 몬스터 HP/ATK는 **밸런스 기준의 원본/참고 데이터**로 취급한다.

실제 전투에서 사용할 HP/ATK:

```text
XML 몬스터
→ 레벨/등급/DEF 등의 콘텐츠 정보 읽기
→ BattleBalanceCalculator 계산
→ 계산된 HP/ATK 사용
```

반면 다음 데이터는 계속 XML 원본을 존중한다.

```text
몬스터 이름
레벨
DEF
EXP
Dungeon
grade/form
placement
```

이렇게 하면 콘텐츠 디자이너가 XML에서 몬스터의 방어력이나 경험치 등을 조정하면서도 HP/ATK는 밸런스 수식으로 관리할 수 있다.

---

## 13. 현재 구조에서 쉽게 조정할 수 있는 값

`BattleBalanceCalculator.js`의 설정값을 중심으로 조정한다.

```js
CONFIG.difficulty.normal.ttkRounds
CONFIG.difficulty.rare.ttkRounds
CONFIG.difficulty.boss.ttkRounds

CONFIG.difficulty.normal.survivalMultiplier
CONFIG.difficulty.rare.survivalMultiplier
CONFIG.difficulty.boss.survivalMultiplier
```

추후 필요하면 다음 단계도 데이터화할 수 있다.

```text
레벨별 TTK 보정
몬스터 역할별 HP 배율
몬스터 역할별 ATK 배율
던전별 난이도 보정
지역별 성장 곡선
```

핵심 계산 엔진을 수정하지 않고 **설정값만 변경하는 방향**을 우선한다.

---

## 14. 향후 확장 방향

현재 단계에서는 완벽한 밸런스 수치를 확정하는 것보다 수식을 유연하게 만드는 것이 우선이다.

권장 순서:

### 단계 1 — 현재 구조

```text
고정 레벨 기준 캐릭터
→ 기준 장비
→ DPS
→ 등급별 TTK
→ 몬스터 HP/ATK
```

### 단계 2 — 전체 레벨 검증

```text
Lv.1~50
×
일반/희귀/보스
```

의 결과를 표로 출력한다.

### 단계 3 — 성장 곡선 확인

```text
Lv.1 → Lv.10 → Lv.20 → ... → Lv.50
```

에서 캐릭터 DPS와 몬스터 HP/ATK가 급격하게 튀는 구간을 확인한다.

### 단계 4 — 필요할 때만 보정

예:

```text
HP = PartyDPS × TTK × DungeonModifier
```

또는:

```text
ATK = CalculatedATK × DungeonModifier
```

처럼 보정 계수를 추가한다.

## 15. 절대 지켜야 할 원칙

### 원칙 A — 현재 플레이어를 몬스터 스케일링에 사용하지 않는다.

```text
현재 장비 강화
≠ 몬스터 HP 증가
```

### 원칙 B — 레벨이 다른 몬스터는 서로 독립된 기준으로 계산한다.

```text
Lv.30 몬스터
→ Lv.30 기준 전투력으로 산정

Lv.50 몬스터
→ Lv.50 기준 전투력으로 산정
```

### 원칙 C — 고레벨 캐릭터가 저레벨 몬스터를 빨리 잡는 것은 정상이다.

이것이 성장 체감이다.

### 원칙 D — XML의 실제 콘텐츠 값과 수식 기반 밸런스 값을 분리한다.

### 원칙 E — 완벽한 숫자보다 조정 가능한 수식 구조를 우선한다.

---

## 16. 한 줄 요약

```text
몬스터는 '현재 플레이어'를 보고 강해지는 것이 아니라,
'그 몬스터 레벨에서 기대하는 기준 전투력'을 보고 설계된다.

플레이어가 강해지면 몬스터가 강해지는 것이 아니라
같은 몬스터를 더 빨리 잡게 된다.
```

이 원칙을 기준으로 향후 몬스터/캐릭터/장비 밸런스 수식을 확장한다.
